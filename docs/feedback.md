# Feedback Guide

High-quality feedback helps shape Reflective faster.

## Good Feedback Includes

- the workflow you were trying to run;
- where current tools break down;
- what Reflective should know before acting;
- what a good outcome would look like;
- what risk or constraint the harness must respect;
- whether this is for an individual developer or a team.

## Useful Issue Types

- **Bug**: something public or documented does not work as expected.
- **Feature request**: a specific capability or workflow you want supported.
- **Feedback**: what is clear, confusing, exciting, or missing.
- **Skill/hook proposal**: a reusable workflow pattern worth making public.

## Sanitization Checklist

Before posting, remove:

- credentials and tokens;
- private file paths;
- customer names;
- internal hostnames;
- proprietary source snippets;
- unredacted logs;
- invite links or session URLs.
